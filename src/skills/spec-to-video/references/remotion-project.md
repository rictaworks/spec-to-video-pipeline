## 1. プロジェクト構成

- コンポジションはシーン単位で定義し、シーン内をカット単位で分割します
- 素材の参照先は素材台帳（`data/clips.json`）の `file_path` です。台帳を経由せずにファイルを直接参照しません
- 採用済み（`adopted` が真）の素材のみを合成に用います
- 字幕とオーバーレイは、素材とは別の層として重ねます。素材そのものへ焼き込みません

## 2. 素材の正規化

**生成した素材をそのまま合成へ渡しません。** 生成側の都合（フレームレート・音声の有無・符号化の仕方）が合成側の要求と一致しないためです。

そろえずに渡すと、素材そのものは壊れていないのに合成側で読めません。しかもその症状は「素材が壊れている」ように見えるため、**素材の作り直しという誤った対処へ進みます。作り直しは課金を伴い、しかも原因ではありません。**

そろえる項目は次のとおりです。既定値に任せません。

| 項目 | 内容 | そろえない場合に起きること |
|---|---|---|
| フレームレート | 出力規格に一致させる（固定フレームレート） | 合成側の補間任せになり、動きが不均一になる |
| 音声 | 生成音声を除去し、無音のトラックを残す | 音声トラックが無いと、合成側が素材の情報を読めずに落ちる |
| 符号化 | 全フレームをキーフレームにする（または相当の指定） | 先頭以外の位置の取り出しに失敗する |
| 索引 | 先頭に置く | 読み出しの開始に時間がかかる、または失敗する |

**元の生成物は上書きせず、別の場所に残します。** 素材台帳の `source_file_path` から参照できるようにします。生成のやり直しは課金を伴うため、そろえる作業をやり直せる状態を保ちます。

正規化は `scripts/normalize_materials.js` を窓口とします。そろえていない素材が P12 へ渡った場合は停止します。

### 素材台帳へ記録する項目

| 項目 | 内容 |
|---|---|
| `normalized` | そろえ済みかどうか |
| `source_file_path` | そろえる前の素材の場所 |
| `file_path` | そろえた後の素材の場所（合成が参照するのはこちら） |

## 3. 実装制約

**描画はフレーム番号に依存する純粋関数として実装します。** 同じフレーム番号に対しては常に同じ結果を返す必要があります。

- 乱数・現在時刻・外部通信を描画の中で使いません。ゆらぎが必要な場合は、フレーム番号から決定的に導出します
- 前のフレームの状態を持ち越しません
- この制約が守られていないと、レンダリングのたびに結果が変わり、再レンダリングでの検証が成立しません

## 4. カット単位の同期

- 各カットの音声（`cuts[].audio_path`）を、そのカットの区間に配置します
- アニメーションの区切りはカット境界に合わせます
- カットの生成尺がシーン尺を超える場合、**超過分は合成側のトリムで吸収します**。素材を作り直しません
- カット数は設計書の指定に一致させます。合成の都合で増減させません

## 5. 遷移の実装方針

- 遷移はカット境界にのみ置きます
- 遷移区間で輝度が急激に変化する実装を避けます。光感受性の検証で不適合となる主要因です
- 遷移の重なり時間は設定ファイルで定めます

## 6. 出力規格の設定

解像度・フレームレート・コーデック・音声形式は、動画設計書の `output_spec` から設定します。既定値で補完しません。

- `output_spec` が確定していない場合、P12 は実行せずに停止します
- 出力先は `out/final.mp4` です
- レンダリング回数は `out/cost_log.json` の `render_count` に計上します
- **レンダラーは完了を待ってから次へ進みます。** Remotion の書き出しは非同期であり、待たずに戻ると mp4 が書き出される前に工程が終わったように見えます

## 7. レンダリングの設定と素材の描画

### 6.1 既定値に任せない設定

レンダリングの並列度と待ち時間の既定値は、**実行機の実装メモリと論理プロセッサ数から決まります。** 空きメモリの小さい環境では、既定値のままだと復号処理が外部から終了させられ、レンダリングが完走しません。

次の3項目は P12 で明示します。

| 項目 | 内容 | 明示しない場合に起きること |
|---|---|---|
| 並列度 | 同時に描画するフレーム数 | 論理プロセッサ数に応じて増え、復号処理が資源を使い切って終了させられる |
| フレーム取得の待ち時間 | 1フレームの素材取得を待つ上限 | 既定の待ち時間に収まらず、素材が健全でも時間切れになる |
| 動画の先読み量 | 復号済みフレームを保持する量 | 実装メモリから決まるため、空きが小さい環境で使い切る |

### 6.2 資源不足の見分け方

次の症状は、**素材ではなく実行環境の問題です。**

| 症状 | 意味 |
|---|---|
| 復号処理が信号で終了させられる | 資源不足で外部から止められた |
| 健全な素材に対して「その位置にフレームが無い」と出る | 復号処理が落ちた結果として現れる |
| 実行のたびに別の素材で停止する | 素材固有ではない |
| 素材取得の待ち時間が既定の上限に達する | 同上 |

**切り分けは、同じ素材を外部の変換ツールで全フレーム復号できるかどうかで行います。** 復号できるなら素材は健全であり、差し戻し先は P11・P12 です。**この症状で素材を再生成しません。課金を伴ううえ、原因ではありません。**

### 6.3 クリップの描画に用いる要素

既定は、素材を別プロセスで復号する方式（`OffthreadVideo`）です。決定的で、描画側の負荷が小さいためです。

ただしこの方式は、素材を一時ファイルへ複製して別プロセスで復号します。**資源不足の影響をまともに受けるため、6.2 の症状が出る環境では完走しません。** その場合はブラウザ側で復号する方式（`Video`）へ替えます。

| 方式 | 使いどころ | 注意 |
|---|---|---|
| 別プロセスで復号 | 既定 | 資源不足の環境では完走しない |
| ブラウザ側で復号 | 6.2 の症状が出る環境 | **読み込み待ちの指定が必須。** 指定しないと各クリップの先頭フレームが黒くなる |

**ブラウザ側で復号する方式に替えるときは、読み込み待ちの指定を必ず併せます。** 先頭が黒いだけでは書き出しは成功するため、機械検証（P13）でも検出されず、人間審査まで残ります。

### 6.4 前提ゲート（P2）での確認

P2 で実行環境の空きメモリを確認し、少ない場合は 6.1 の設定を先に決めます。レンダリングが数十分かかってから落ちると、そのぶんが無駄になります。
- レンダリングが失敗した場合、レンダ回数を加算しません

## 8. 演出の選定（P7）

工程 P7 では、カットの割り方に加えて**演出の各要素をエージェントが選定し、台本台帳へ記録します**。合成側は記録に従って実装し、記録に無い演出を足しません。

選定する要素は 6.1 から 6.6 です。

### 6.1 トランジション

カット境界とシーン境界に置くトランジションは、**動画設計書の内容からエージェントが選定します**。選定結果は台本台帳へ記録し、合成側はその記録に従って実装します。実装者が場当たりに決めません。

#### 対応表

| 設計書から読み取れる意図 | 選ぶ遷移 | 既定の長さ | 理由 |
|---|---|---|---|
| 同一シーン内のカット送り | クロスディゾルブ | 0.3〜0.5 秒 | 最も標準です。輝度が急に変わらず、視線の連続性を保てます |
| 場面が変わる（別の場所・別の対象へ） | カット切り替え（遷移なし） | 0 秒 | 切り替わったことを明確に伝えます。冗長な遷移を挟みません |
| 章の区切り・時間経過 | 暗転 | 0.5〜0.8 秒 | 区切りを強く示します。**光感受性の観点から、連続して用いません** |
| 回想・明転 | ホワイトアウト | 0.5〜0.8 秒 | 時間軸の移動を示します。暗転と同じく連続して用いません |
| 図解の要素が順に増える | 遷移なし（要素ごとの出現） | 0 秒 | 図解内の変化であり、カットの切り替えではありません |
| 締めくくり・タイトルカードへ | クロスディゾルブ | 0.5 秒 | 余韻を残します |

#### 制約

- **既定はクロスディゾルブです。** 迷った場合はこれを選びます
- **輝度が急激に変わる遷移（暗転・ホワイトアウト）を既定にしません。** 光感受性の検証で不適合となる主要因です。使う場合は設計書に区切りの意図が読み取れる場合に限り、隣接して繰り返しません
- 1つの動画で用いる種類は3種類までに収めます。種類が増えるほど、視聴者は遷移そのものに注意を向けます
- 遷移の長さがカットの尺の 20% を超える場合は、遷移を短くします。素材が見えている時間を確保するためです
- 設計書に演出の指定がある場合は、指定を優先します。指定と本表が矛盾する場合は停止し、設計書の確認を求めます

#### 台帳への記録

台本台帳の `scenes[].transitions[]` に、次を記録します。

| 項目 | 内容 |
|---|---|
| `at_cut_id` | 遷移を置くカット（そのカットの開始位置に置きます） |
| `kind` | `cross_dissolve` / `cut` / `dip_to_black` / `dip_to_white` |
| `duration_sec` | 遷移の長さです。`cut` の場合は 0 です |
| `reason` | 6.1 のどの意図に該当するかを、設計書の記述に触れて書きます |

記録が無いカットがある場合、P11 の入口ゲートで停止します。合成側が既定値で補完しません。

### 6.2 動きの質感（補間）

| 意図 | 選ぶ補間 | 理由 |
|---|---|---|
| 既定 | イーズイン・イーズアウト | 始まりと終わりが緩み、目に馴染みます |
| 機械的・無機質な表現 | リニア | 等速の硬さをそのまま利用します |
| 切り替え・パラパラ表現 | ホールド | 値を保持し、次の位置で瞬時に切り替えます |

**既定はイーズです。** リニアは、等速であることに意味がある場合に限って選びます。

### 6.3 エフェクト

- **既定は使いません。** 使う場合は目的（可読性の確保・強調・不要部分の抑制）を記録します
- ぼかし・ズームは、輝度と規則的パターンに影響します。画面の大部分に掛ける場合は、機械検証で検出されうることを前提に選びます
- 見た目を整えるためだけの追加は行いません

### 6.4 カラー

| 項目 | 目安 |
|---|---|
| 輝度の範囲 | 黒 0 IRE / 白 100 IRE を超えないこと |
| 全体のバランス | 各色成分の上端と下端が揃っていること |
| 配色 | 設計書の指定に従います。指定が無い場合は補完せず、設計書の追記を求めます |

### 6.5 合成（不透明度・描画モード）

| 描画モード | 扱い |
|---|---|
| 通常 | 既定です |
| 乗算・比較（暗） | 暗くなる方向のため、輝度の上振れは起きません |
| 加算・スクリーン・比較（明） | **輝度が上がりやすく、光感受性の検証で不適合となりやすい**ため、選ぶ場合は理由を記録します |

### 6.6 音

- 設計書の `output_spec.audio` に従います。音声を持たない指定であれば、音の演出は選定しません
- 音声を持つ場合の目安は、配信向けで -14 LUFS 前後、トゥルーピークは -1 dBTP 以下です
- 処理の順序は、不要な低域の除去 → 雑音の低減 → 帯域の整理 → 歯擦音の抑制 → 音量差の圧縮 → 音量の調整 → 最終保護、の順とします

### 6.7 テロップ

- 座布団（背景の帯）を敷かず、フチ処理で視認性を確保します
- 画面下 15% はシステム字幕の領域として空けます。テロップを下端に固定しません
- フチは内側に濃色、外側に差し色を置きます。外フチの色が作品の識別色になります

#### フチの幅

**フチの幅は字の大きさに対する比で定めます。固定値で書きません。**

固定値にすると、字の大きい見出しに合わせた幅が、字の小さい常設テロップでは字の内側まで食い込み、判読できなくなります。**潰れても書き出しは成功するため、機械検証（P13）では検出されません。人間審査（P14）まで残ります。**

| 用途 | 幅の目安 |
|---|---|
| 外フチ | 字の大きさの 0.15〜0.20 倍 |
| 内フチ | 字の大きさの 0.05〜0.10 倍 |

#### フチの色

**外フチの色は、明るい背景と暗い背景の双方で判読できるものに限ります。白のみの指定を認めません。**

外フチを白にすると、淡色の図解カットの上でフチが消え、文字が読めなくなります。生成クリップ（暗めの実写）では白フチが効くため、**クリップだけを見て確認すると見逃します。**

#### 常設テロップと図解の重なり

常設テロップと章タイトル字幕が占める下端の帯を定め、**図解はこの帯に掛からない範囲へ収めます。** クリップは全面のままでかまいません。

図解は画面いっぱいに描かれるため、そのまま置くと下部（凡例・対象の列挙など）がテロップに隠れます。図解の文言は台本台帳で確定した内容であり、隠れてよい情報ではありません。

帯の高さは、常設テロップと章タイトル字幕の両方が収まる高さにします。章タイトル字幕を帯の上端に合わせると、図解へ掛かります。

#### 判読性の確認

**判読性の確認は、暗い実写カットと淡色の図解カットの双方で行います。** 片方だけでは、背景との同化を見逃します。この確認は人間審査（P14）の項目です。

**字幕（SRT）とテロップは別物です。** 字幕は受信側が描画し、テロップは映像に焼き込みます。同じ位置に同じ意匠で重ねると、視聴者が字幕を表示したときに画面が潰れます。

### 6.8 台帳への記録（演出）

台本台帳の `scenes[].direction` に、次を記録します。

| 項目 | 内容 |
|---|---|
| `motion_easing` | `ease` / `linear` / `hold` |
| `blend_mode` | `normal` / `multiply` / `screen` / `add` |
| `telop_pattern` | `multi_outline` / `plain` |
| `effects` | 使う場合のみ。名称と目的を書きます |
| `color_note` | 配色の根拠（設計書のどの記述に従ったか） |
| `blend_reason` | 輝度が上がる描画モードを選んだ場合の理由 |

記録が無いシーンがある場合、P11 の入口ゲートで停止します。
