# Remotion 単独モードの手順

`production_mode` が `remotion_only` の場合に、工程 P8〜P10 で読み込みます。生成主体モードの場合はこのファイルを読み込みません。

## 目次

1. 工程の対応
2. 手描き表現の規約
3. アニメーション図解の設計
4. 3D 素材の適用条件
5. モード整合の確認

---

## 1. 工程の対応

| 工程 | 生成主体モード | 本モード |
|---|---|---|
| P8 | 起点画像を生成します | 該当しません |
| P9 | image-to-video でクリップを生成します | 手描き表現のシーンを実装します |
| P10 | 静的図解を生成します | アニメーション図解を実装します |

本モードでは生成 API を呼びません。したがって生成に伴う課金は発生せず、課金の対象はレンダリング回数のみです。

## 2. 手描き表現の規約

- 描画はフレーム番号に依存する純粋関数として実装します（`remotion-project.md` 2 節）
- 図形・線・塗りの定義は設定ファイルへ分離し、コンポーネント内に数値を直書きしません
- 配色は動画設計書の指定に従います。指定がない場合は既定値で補完せず、設計書の追記を求めます

## 3. アニメーション図解の設計

- 図解内の文言は、P3 で校正が完了しているものだけを用います
- 文言はテキストとして描画します。画像に焼き込みません。修正時に再レンダリングだけで済ませるためです
- 要素の出現順は、ナレーションのカット境界に合わせます

## 4. 3D 素材の適用条件

次のいずれかを満たすカットに限り、3D 素材を用います。満たさないカットで 3D を使いません。

- 3D 空間への配置が必要である
- カメラの移動が必要である
- 物理演算が必要である

適用する場合は、ヘッドレス実行で連番画像として書き出し、素材台帳へ登録してから合成します。書き出した連番は他の素材と同じく採否の対象です。

## 5. モード整合の確認

本モードは、視聴者がそのまま入力することを想定する文字列（コマンド・URL・コードなど）を画面に出す用途に適します。

生成主体モードの設計書にそうした文字列が含まれる場合は、**モード選定の誤り**として停止します。代替表現による回避を行いません。
