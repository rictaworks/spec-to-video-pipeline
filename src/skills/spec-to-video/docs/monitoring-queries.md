# 監視用クエリ集

requirements.md 22節の定期確認に用います。対象は Claude Code / Codex / Antigravity の3ホストです。

## 1. 発火すべきクエリ

いずれも複数の手順を要します。単純な一手で完了する照会は含めません。

| # | クエリ | 期待 |
|---|---|---|
| 1 | `docs/video-spec.md の設計書で動画を作ってください` | P1 から開始します |
| 2 | `設計書のシーン3だけ素材を差し替えて、mp4 を作り直してください` | 対象シーンに限定して実行します |
| 3 | `台本は確定済みです。字幕だけ作り直してください` | 台帳の充足を確認し、P6 から実行します |
| 4 | `素材は採用済みなので、レンダリングと検証だけ回してください` | P12 から実行します |
| 5 | `この設計書、明滅の検査まで通るか確認してください` | P1 から P13 まで実行します |

## 2. 発火すべきでないクエリ

| # | クエリ | 期待 |
|---|---|---|
| 1 | `動画を作りたいので構成を考えてください` | 使用しません（設計書の作成は範囲外です） |
| 2 | `この mp4 を1分に切り詰めてください` | 使用しません（設計書起点ではありません） |
| 3 | `完成した動画を YouTube に上げてください` | 使用しません（人間の手動工程です） |
| 4 | `設計書のシーン数を教えてください` | 使用しません（単純な照会です） |
| 5 | `out/final.mp4 のファイルサイズを見てください` | 使用しません（単純な照会です） |

## 3. ホスト間の挙動差の確認

3ホストで同一のクエリを実行し、次の一致を確認します。

- 停止した工程
- 差し戻し先
- 出力ファイルの構成

差が出た場合は、内容・発生ホスト・対応方針・確認日を記録します。対応の順序は requirements.md 21.3 に従います。

## 4. 参照ファイル未読時の確認

参照ファイルを読み込まない条件で実行し、**ゲートで停止すること**を確認します。

| 読み込ませないファイル | 期待する停止 |
|---|---|
| `references/design-doc-schema.md` | P1 で正規化できず停止します |
| `references/cost-and-credentials.md` | P2 の前提ゲートで停止します |
| `references/narration-subtitles.md` | P4 で話者とエンジンが確定せず停止します |
| `references/remotion-project.md` | P11 で構成規約が確定せず停止します |
| `references/compliance-review.md` | P13 で判定基準が確定せず停止します |

停止せずに進んだ場合、入口ゲートが機能していません。

## 5. 記録

確認日・使用したホストとそのバージョン・結果を `docs/references.md` へ追記します。誤発火または未発火が見つかった場合は、`description` を改善して再配布します。
