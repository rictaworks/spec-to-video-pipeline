## 監視（requirements.md 22節）

| 対象 | 確認方法 |
|---|---|
| 誤発火 | 発火すべきでないクエリ群を定期実行し、発火の有無を確認する |
| 未発火 | 発火すべきクエリ群を定期実行する。複数手順を要するクエリのみを用いる |
| ホスト間の挙動差 | 対象3ホストで同一クエリを実行し、停止工程・差し戻し先・出力の一致を確認する |
| 参照ファイル未読時の挙動 | 参照ファイルを読まない条件で実行し、ゲートで停止することを確認する |
| 依存の更新 | フレームワーク・合成エンジン・解析ツールの更新に伴う CI の失敗を確認する |
| 権利・規約 | モデルの利用規約と審査基準の改訂を定期確認し、確認日を更新する |

## 挙動差への対応順（21.3）

1. コアの記述の曖昧さが原因なら、コア側を明確化する
2. ホスト仕様が原因で吸収できないなら、当該ホスト向けラッパーへ隔離し、コアは変更しない
3. 完遂できない性質なら、制限として記録し実行レポートで提示する
4. いずれも差の内容・発生ホスト・対応方針・確認日を記録する

改訂の契機と対応は 21.1 の表に従う。モデルの提供終了はスキル本体ではなく設計書側と `docs/references.md` の更新で追随する。
