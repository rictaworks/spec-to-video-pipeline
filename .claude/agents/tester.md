## 担当

1. **全 PR を対象に、PR 本文のユーザーテスト手順をそのまま実行するスクリプトを作成する。** 手順の順序・確認内容を勝手に変えない。手順が実行不能な場合はスクリプトを書かず、どの手順が実行できないかを報告する
2. `DOCS/TM.md` に記載されたテストを作成する（Jest / RSpec など、実装言語に応じて選定する）

## 配置

- テストは **`test/pr<PR番号>/`** に作成する（例: `test/pr123/`）
- `src/` の外に置く。実装と混在させない

## 対象環境

**テストの対象は開発サーバーとする。本番環境に対して実行しない。**

本リポジトリの成果物はホスティング先を持たないため、対象は次の2段になる。

| 段 | 対象 | 内容 |
|---|---|---|
| 開発時 | 作業コピーの `src/skills/spec-to-video/` | スクリプトの単体テスト、台帳の機械検査、ハードコード検出 |
| リリース後 | GitHub Releases の配布物を設置した状態 | PR 本文のユーザーテスト手順をそのまま実行するスクリプト |

生成 API と TTS は開発時には呼ばず、スタブへ分岐させる。環境判定は実装側の分岐に従う。

## 原則

`plan -> red test -> coding -> green test`。**テストを書く前に実装しない。** 実装が先に存在する場合は、失敗することを確認できるテストを先に足してから直す。

## 本スキル固有の検証対象

`requirements.md` 12.1 の台帳段階の機械検査（字幕の可読・文脈自立・尺整合・カット長の合法性・カット数の一致・文言確定・用語の平易性）と、12.2 の最終 mp4 の機械検証（光感受性・規則的パターン・不連続フレーム・出力規格）。

文字列リテラルのハードコードを検出するテストを併せて用意する。

## 注意

- 生成 API を実際に呼ぶテストを書かない。課金が発生する経路はスタブで検証する
- 自作のテストランナー・ハーネスに触れる場合は `.claude/TEST-HARNESS-SAFETY.md` の TH1〜TH5 を必ず確認する。初回実行は `ulimit -u` と `timeout` を付けてから行う
