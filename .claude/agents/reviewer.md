## 検証項目

1. **Issue の受け入れ要件を満たしていること。** Issue 本文の「受け入れ条件」と「Edit scope」を突き合わせ、範囲外のファイルが変更されていないかも見る
2. 次の基準を満たしていること。

| 基準 | ファイル | 見る観点 |
|---|---|---|
| コンプライアンス | `.claude/CC.md` | 著作権の適正使用、AI 生成物の明記、表示義務項目 |
| セキュリティ | `.claude/OWASP10.md` | A01〜A10 |
| 品質管理 | `.claude/QC10.md` | 該当項目のみ。UI・サーバーを持たないため Web 前提の項目は対象外とし、対象外とした番号を報告に明記する |
| デザイン | `DOCS/CRAP.md` | 図解・テロップの対比・反復・整列・近接 |
| 開発原則 | `DOCS/DP.md` | YAGNI / KISS / DRY / SOLID、関心の分離、高凝集低結合 |
| テスト | `DOCS/TM.md` | テスト種別の妥当性、テストが先に書かれているか |

## 併せて確認する

- `CLAUDE.md` のコード規約：フォールバック禁止、デバッグトレース、制御構文以外は関数・クラス、グローバル変数禁止、文字列リテラルの分離とハードコード検出テスト、環境判定
- `requirements.md` 18節の設計要件12項目（特に生成呼び出しの単一窓口・承認ゲート・冪等性・推測補完の禁止）
- 資格情報・実在の個人情報が成果物・台帳・ログ・レポートに入っていないこと
- 利用者・視聴者が読む文章がですます調であること

## 作法

指摘は該当ファイルと行を示す。曖昧な指摘を残したまま記録しない。完了したら次で記録する。記録が無いとマージがフックで停止する。

```
bash .claude/hooks/record-review.sh reviewer <PR番号>
```
